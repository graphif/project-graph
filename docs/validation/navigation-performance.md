# 画布平移与缩放性能

## 改动与复用

- 系统主题查询缓存一秒，避免每条连线、每次布局触发桌面主题查询。
- 分组布局只在成员、坐标、尺寸或相关属性变化时更新；静止节点不重复执行物理层级排序。
- 世界坐标曲线、碰撞形状和屏幕缩放分别缓存；连线命名沿世界曲线定位，文字未变时复用排版。反向连线的命名位置缓存随端点、命名和对象生命周期失效。
- 分组概览复用字体测量、主题和布局，保留圆角、50% 透明覆盖与内部内容。

先核查并采用 Godot 内置的 `Transform2D * Rect2`、`Transform2D * PackedVector2Array`、`Curve2D.tessellate`、`Curve2D.sample_baked` 和 Dictionary 缓存，不新增第三方依赖，也不另写通用曲线细分或包围盒算法。所有画面仍通过场景节点显示。

Godot 文件通过 MCP 的脚本读取、修改、创建和编辑器脚本执行工具处理；没有文本读取或编辑 `.tscn`。

## 可重复测试

经用户授权，通过 Godot MCP 执行：

```sh
godot --path . --display-driver x11 --script res://tests/run_navigation_benchmark.gd -- --screen=0
```

`--screen=N` 指定屏幕；可追加 `--uncapped` 测试取消垂直同步后的吞吐量。默认保持项目的同步设置。测试创建独立的 6 个分组、24 个成员和 18 条命名连线，冻结节点并关闭测试实例的物理避让，不打开或保存用户文档。预热后分别测量静止、平移和连续缩放三秒，输出实际帧间隔的平均 FPS 和 p95 毫秒。它不以受机器负载影响的 FPS 数字作为自动化通过条件。

发布版测量：通过 MCP 使用 PackedScene API，将 `tests/navigation_benchmark.gd` 挂到临时 Node 场景；临时设置该场景为主场景导出发布版，随后恢复项目配置并删除临时场景。正式安装包使用原主场景，不包含性能测试入口。

2026-09-29，本机 Intel Iris Xe、Godot 4.8.dev6、Compatibility 渲染、X11、1280×800 窗口、119.96 Hz 屏幕、垂直同步开启：

| 发布版 | 平移 FPS | 缩放 FPS | 平移 p95 | 缩放 p95 |
| --- | ---: | ---: | ---: | ---: |
| 临时恢复本次优化前代码的对照版本 | 14.4 | 13.9 | 78.3 ms | 85.0 ms |
| 本次优化后 | 120.0 | 119.0 | 9.5 ms | 9.4 ms |

上述对照在旧版应用已退出后的同一桌面负载条件下执行。此前旧版应用仍运行时，优化版同图的平移约 130 FPS、缩放约 110 FPS（取消垂直同步）；不能把旧实例退出带来的全部改善归因于代码。平均接近 120 FPS 不代表每一帧均小于 8.33 ms，也不保证任意图规模、硬件和背景负载均达到 120 FPS。75 Hz 屏幕上的同步刷新受其刷新率限制。

## 回归结果

通过：`navigation_cache_smoke`、`theme_canvas_sync_smoke`、`edge_caption_smoke`、`edge_caption_magnet_smoke`、`text_edit_geometry_smoke`、`canvas_text_focus_smoke`、`group_overview_smoke`、`node_repulsion_smoke`、`container_opacity_smoke`、`arrow_geometry_smoke`、`connection_continuity_smoke`、`canvas_zoom_reference_smoke`、`edge_contrast_smoke`、`pinch_zoom_smoke`。输入与右键交互测试使用图形显示服务器执行；无头显示服务器缺少 IME，并不能可靠替代真实窗口的右键输入测试。

`continuous_corners_smoke` 中“小控件必须为 StyleBoxFlat、必须采用固定半径”的断言失败；临时恢复全部本次性能修改后仍得到相同失败。原因是工作区已有、未纳入本次提交的小控件 SVG 圆角改动。没有为了通过旧断言而覆盖该改动。分组概览圆角与透明预览测试通过。

后续发布整理时，该既有 SVG 圆角实现已独立提交，测试也按其设计契约更新为共享抗锯齿样式与受限组件半径；`continuous_corners_smoke` 已重新通过。

运行过发布导出、独立图形启动、脚本检查及 `git diff --check`。未安装额外格式工具。

## 用户手动验证（待执行）

1. 保存文档并重新启动更新后的应用，将窗口移到 120 Hz 屏幕。打开“窗口 → 切换调试信息展示”。连续拖动画布和滚轮/触控板缩放，应接近显示器刷新率；`FPS` 为实际渲染帧率，`PFPS` 是配置的物理更新频率，二者不必相同。若仍固定 60，先核对窗口所在屏幕的系统刷新率、是否仍有旧实例，以及图规模和后台负载。
2. 对节点和连线命名连续输入中文、英文，执行全选、中间插入、Home/End，再撤销/重做。应保留光标与完整文字；若失败，重点检查输入前缀截断、横向滚动和选区丢失。
3. 移动端点、添加/删除反向连线、清空并恢复命名；命名应跟随连线，重新分配位置，磁性避让继续生效。右键线段或命名块改色，应改变整条连线。重点检查缓存失效后的位置、颜色与点击区域。
4. 缩小分组至概览并放大回来，应保持圆角及半透明内部内容；改名、改变填充色、移入/移出成员后应立即更新。重点检查标题残留、边框未跟随内容或放大后无法选择内部节点。

最终交付复测：原生 Wayland 窗口中的文本全选/插入/拖选和连线右键改色测试均通过。X11 的合成输入运行出现拖选与右键命中失败，不能据此宣称 X11 输入路径已通过；该路径仍需真实鼠标手动验证。性能基准继续使用 X11，几何和缓存断言通过。
