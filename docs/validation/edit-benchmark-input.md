# 拖动基准输入更正

旧 large_edit_benchmark 注入鼠标事件，却没有把实际系统指针移到事件位置；CanvasItem.get_global_mouse_position 可能仍读取原指针位置，因此报告高帧率但对象并未运动。

复用原生 Viewport.warp_mouse 设置测试窗口内的指针，同时保留真实输入回调和刚体积分。结束后断言驱动对象实际移动至少 20 世界单位；测分组时逐个检查所有后代具有相同位移。源文件哈希继续校验。没有新依赖，使用 Godot MCP 脚本读写和编辑器执行工具。

更正后的基准在移动布局优化前测到普通节点 p95 253.57 ms、51 后代分组 p95 324.63 ms，均触发原有 33.34 ms 预算失败；因此撤回旧基准约 120 FPS 的真实拖动结论。移动布局优化后的同一发布版、同一 1029 对象文件、119.96 Hz 显示器及垂直同步，节点 93.63 FPS/p95 12.96 ms，分组 61.26 FPS/p95 22.45 ms，真实位移和预算检查通过。详情见 moving-layout-cache.md。这里记录一次 1.2 秒采样，不保证任意图规模或持续 120 FPS。

待用户手动验证：打开大图实际拖动节点和分组，观察 FPS 与对象是否跟随指针；如果画面流畅但节点不动，测试不能算通过。测试窗口会使用原生 API 移动指针，实际桌面、高 DPI、长期拖动与松手惯性仍待人工确认。
