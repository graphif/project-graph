# 缩放缓存失效修复

教程操作真实文件有 1029 个对象。`zoom_frame_benchmark.gd` 经 SubViewport 原生 MagnifyGesture 路径连续缩放，覆盖 0.35–0.75 及 0.025–1.5 倍率的重复往返，检查文档哈希、对象坐标和布局版本不变。原来局部最大帧时约 270 ms，广范围 p95 约 166–185 ms；仅用 ±25% 的目标倍率测试未充分覆盖这些采样阈值。

停用布局、预览和连线回调仍出现采样阈值停顿；固定视口采样的对照消除了该规律性尖峰。实际修改固定舞台视口采样，画布字形使用独立 2 倍原生 FontFile 缓存和 mipmap；节点圆角复用既有 SVG → 4 倍 ImageTexture/mipmap 实现，UI 继续使用原生 DPITexture。渐进载入计划与新节点使用同一字体策略。只改变显示缓存，不改变文档几何、输入锚点或碰撞。

评估 Godot 原生 FontFile oversampling、mipmap、MSDF 和项目已有纹理缓存后，复用前两者及既有 SVG 适配。大尺寸 CJK MSDF 的首次生成成本已在加载工作中出现，不新增通用渲染库或依赖。[FontFile 文档](https://docs.godotengine.org/en/latest/classes/class_fontfile.html)说明字体可覆盖视口采样；[DPITexture 文档](https://docs.godotengine.org/en/latest/classes/class_dpitexture.html)说明其栅格化跟随画布采样。

同一 X11 / Compatibility / Iris Xe / 1280×800 环境，修改后局部约 130 FPS，p95 13.6 ms、最大 17.1 ms；广范围约 88 FPS，p95 34–37 ms、最大 49.6 ms。预览切换与全图渲染仍有慢帧，严格 120 Hz 预算尚未通过。后台负载也能造成独立尖峰；不承诺所有硬件与图规模都零掉帧。

采样缓存、实际圆角像素、画布 AA、缩放基准、手势、导航缓存、连续圆角、文字编辑、渐进加载及交互外观回归通过。AA 测试单独禁用预览，以保留描边采样与像素检查；量化描边允许既有 4.5% 档位误差。正常最大倍率 3.0 下弧线区域测得 102 个半透明边缘像素。原 20–50 倍测试超出相机交互上限，本次将质量验收覆盖改为实际支持的倍率范围。

Godot 文件通过 MCP 脚本读写、编辑器脚本执行处理。缩放基准可用 `PG_BENCH_DOCUMENT` 指定只读文档，`PG_ZOOM_STRICT=1` 启用严格帧时目标（当前仍可失败）；`PG_ZOOM_ABLATION` 只供诊断，不能作为正常应用性能。

手动验证待执行：重新启动新版本，打开三个教程，在局部与全图间反复捏合或 Ctrl+滚轮缩放，特别跨过 0.25、0.5、1.0 实际倍率。应不再有规律性的秒级冻结，文字和圆角仍清晰；同时检查节点不跳动、曲线与点击命中位置一致。若失败，重点记录对应倍率、文件、FPS 和是否正在切换标题预览。高 DPI、其他 GPU 和发布版实际操作仍需复核。
