# 大图局部渲染与导航验证

日期：2026-10-02。目标是让已有大图的浏览接近 120 Hz，保留文档、碰撞、撤销和嵌套预览语义。当前有足够的平均帧率余量，但连续缩放仍有慢帧，不能承诺稳定锁住 120 FPS。

## 实际改动

- Stage 维护文档与几何版本。保存状态、状态栏计数、关闭的辅助窗口、容器布局和分组关系只在相关数据改变时重算。编辑中的原生文本控件单独登记，未提交文本仍会标记文档为已修改；保存和重载重置缓存。
- 连线和标题在静止时停止逐帧轮询；端点、样式、标题成员及编辑状态变化会唤醒更新。空选择不遍历整张图，静止实体不处理全局输入或物理回调。
- 相机更新后，Stage 用原生 Rect2/Transform2D 计算当前视口的世界范围，留出 64 屏幕像素余量。视口外的连线和分组预览暂停缩放更新，进入视口时补齐。连线范围包含整条曲线及有效标题，因此两端都在屏幕外、但曲线经过视口的情况仍会更新。世界几何和物理碰撞保留；没有把编辑对象删除或冻结。
- 连线与概览边框的屏幕尺寸按每倍缩放 16 档采样，按对象 ID 分散更新。世界端点、分组边界和标题世界位置不随采样改变；边框和抗锯齿宽度有最多约 4.5% 的档位变化。曲线保持原来的精细采样，没有降低曲线精度换取帧率。
- 分组阈值、祖先关系、隐藏查询及嵌套摘要仍保留；相机变化通常不重建所有隐藏对象的渲染状态。物理避让使用显式实时几何刷新，避免刚体积分早于变换通知时读到旧的标题碰撞位置。

复用 Godot 原生 Rect2、Transform2D、信号、节点处理开关、Array.bsearch、Dictionary 和既有布局/曲线/样式实现，没有新增依赖或自建空间索引。评估过 VisibleOnScreenNotifier2D；实测在这个含多个 SubViewport 的工作区中，通知器对当前舞台视口外的连线仍报告可见，因此最终以当前舞台的原生世界矩形判断，不依赖跨视口可见性通知。

Godot 文件通过 `mcp__godot_mcp__read_script`、`modify_script` 和 `execute_editor_script` 类别处理。场景资源仅通过 PackedScene/ResourceSaver 操作，没有读取场景文本。现有插件和用户其他工作区修改未纳入优化提交。

## 实测

真实文档：`/home/waya/Desktop/project/教程操作.prg`，导入后 1029 对象。Godot 4.8.dev6、Linux X11、Compatibility、Intel Iris Xe，显示器 119.96 Hz，窗口 1280×800、舞台 1280×719。每阶段采样 2.5 秒，用实际相邻帧时间统计，不使用包含载入时间的引擎累计 CPU 监视器。

| 场景 | 平移平均 FPS | 缩放平均 FPS | 缩放 p95 帧时 |
| --- | ---: | ---: | ---: |
| 最初调试版，全图 | 5.46 | 4.19 | 约 497 ms |
| 优化后调试版，局部浏览、关闭垂直同步 | 172.92 | 166.79 | 9.09 ms |
| 优化后发布版，局部浏览、开启垂直同步 | 119.67 | 113.74 | 10.00 ms |
| 优化后发布版，全图、关闭垂直同步 | 149.01 | 122.22 | 10.40 ms |

局部浏览从相机 zoom=0.5 开始，平移幅度 800×400 世界单位，连续缩放幅度 ±25%。全图从适配整个文档开始，包含 87 个分组摘要。局部绘制调用约 130～199 次，全图约 545～605 次；纯相机浏览期间布局版本均未改变。已查看发布版局部渲染截图。

测试隔离配置和数据目录，冻结测试刚体并屏蔽外部输入，使用真实相机平滑和渲染管线。平均 FPS 达到目标所需余量不等于每帧都满足 8.33 ms；硬件、后台负载、视口大小、冷字体缓存和真实输入会影响结果。

可通过 Godot MCP 运行 `tests/large_document_benchmark.gd`，设置 `PG_BENCH_DOCUMENT` 指定只读测试文档；`PG_BENCH_LOCAL=1` 测局部、`PG_BENCH_VSYNC=1` 开同步、`PG_BENCH_SCREENSHOT` 指定截图路径。默认测全图且关闭同步。`PG_BENCH_PROFILE` 和 `PG_BENCH_ABLATION` 仅用于诊断，关闭回调或画布的消融数据不是正常应用性能。

## 已执行检查与限制

导航缓存测试覆盖静止停止轮询、屏幕外缩放不重建几何、屏幕外移动仍更新世界范围、重新进入视口补齐、箭头开关、端点移动、标题同伴变化、包含关系和旋转/缩放/斜切边界。保存状态测试覆盖保存后清除缓存的未保存标记及取消未提交文本。

X11 下 navigation_cache、native_dirty、group_overview（含真实 `你好.prg`）、arrow_geometry、connection_continuity、smooth_connections、edge_contrast、edge_caption、text_edit_geometry、theme_canvas_sync、container_opacity、node_repulsion、linked_attraction、interaction_visual 通过。三个新增 master 文档各自的载入、编辑/撤销、另存/重载、附件完整性及原文件哈希检查通过。

canvas_text_focus 的三项边缘拖动选文失败，以及 edge_caption_magnet 的线身右键及后续配色六项失败，修改前已存在；临时恢复 HEAD 连线/标题脚本再次复现同样六项。优化期间发现新的标题避让重叠，补充物理即时刷新后恢复为原有六项，没有把这两套测试记为通过。

Linux 发布版导出通过；正式主场景可执行文件用三个真实项目参数启动完成，未出现脚本错误，自动退出时有 5 个 ObjectDB 实例泄漏警告，尚未完成正常关闭路径的人工排查。项目配置在导出后按原字节恢复，第三方插件未修改。Godot 编译和 Git 空白检查通过；环境没有 gdformat/gdlint，未运行独立格式化器。其他平台、RPM 安装和真实高 DPI 触控板验收尚未执行。

## 用户手动验证（待执行）

1. 保存已有工作，运行 `dist/project-graph-local-render.x86_64`，将窗口放在系统已设为 120 Hz 的显示器上，打开桌面 project 文件夹中的三个教程。通过调试菜单显示 FPS；放大浏览局部，用 Ctrl+滚轮、触控板捏合和中键平移。应明显更顺畅，局部平移接近 120 FPS；连续缩放仍可能小幅掉帧。
2. 将一片内容移出屏幕，继续缩放，再平移回来；内容、曲线、箭头和标题应立即正确显示。重点检查进入屏幕后缺线、旧线宽、旧标题位置，以及两端均在屏幕外的跨屏曲线消失。
3. 缩小嵌套分组：各层预览应保留，普通细节隐藏；放大后恢复。重点检查外层盖住内层后预览丢失、层级边框错位或隐藏节点参与点击。
4. 拖动节点、改连线标题/颜色、撤销、另存到测试副本并重开。应保持连接、避让、未保存标记与附件。重点检查标题重叠、取消编辑后仍显示未保存标记，或保存后未清除标记。

新可执行文件没有替换已安装程序；文件管理器缩略图系统脚本的安装仍按 Linux packaging README 执行。
