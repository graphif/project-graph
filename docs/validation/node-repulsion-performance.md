## 改动与边界

`src/node_repulsion.gd` 的 `_track` 原先使用 `Array.has` 去重；每个约束最多经过六轮求解，每次修正都可能再次扫描已移动节点。现在用 `Dictionary[int, bool]` 记录实例 ID 集合，`stop_motion` 用 `instance_from_id` 取得仍存在的实体、检查有效性并清空记录。

初版直接以实体作为类型化 Dictionary 键。专项回归发现，已释放实体会在键遍历时触发引擎错误，甚至提前中断清理；因此改为实例 ID。回归将已删除节点放在记录首位，检查之后的存活节点仍能正常停止。

每轮约束求解记录是否实际进入速度修正分支。只有完整一轮没有修正才提前退出：此时下一轮的节点速度、约束和遍历顺序都相同。发生修正的情况仍最多执行六轮，不根据单个约束或近似阈值提前退出。推力、速度上限、容器过滤和历史事务条件不变。

这只减少活跃拖拽和事务收尾的部分脚本开销，不是静止画布、渲染或平移缩放卡顿的完整修复；不能引用旧压测结果作为此次加速证据。

## 复用评估

- 首选引擎内置 `Dictionary`。官方[数据结构说明](https://github.com/godotengine/godot-docs/blob/master/tutorials/best_practices/data_preferences.rst)说明哈希查找特性；[Dictionary 文档](https://docs.godotengine.org/en/stable/classes/class_dictionary.html)说明保留插入顺序。
- 社区通用集合库在这里不提供缺失能力；无需引入额外依赖或自行实现哈希表。项目原脚本已使用类型化 Dictionary 保存实体推力，本次沿用相同语言和运行时能力。
- 没有替换现有物理求解器，提前退出只是现有求解循环的终止条件优化。
