# 缩放细边框缓存

根因：minimum_screen_border 使用经过除乘运算的浮点 basis 作为精确数组缓存键。同一缩放档位也会因浮点尾数变化重建圆角轮廓。只检查自身 visibility_layer，还会继续计算被父级画布遮住的节点。

改为整数缩放档位和近似方向基比较，缓存由尺寸、半径和边宽决定的世界轮廓；烘焙使用 Godot 原生 Transform2D × PackedVector2Array。检查连续 CanvasItem 父链的 canvas_cull_mask，保留 top_level 和普通 Node 断开继承的语义。复用现有 Godot 数学与项目 Corners，没有新增依赖或自制通用多边形库。

通过 Godot MCP 脚本读取、修改和编辑器脚本执行完成。minimum_screen_border_smoke 增加真实微小缩放、遮挡和恢复回归：原实现三个断言失败，修复后通过；原有像素覆盖与字形采样检查仍通过。

1029 对象教程操作.prg、新的一层标题预览开发场景、1280×800、Compatibility、关闭 VSync：相同缩放基准局部约 152 FPS，宽范围冷/热约 111/117 FPS，p95 约 19.6/23.8/17.9 ms。此前局部缩放约 20–40 FPS。测试期间桌面应用仍运行，结果存在负载波动；严格 120 Hz 的 p95≤8.34 ms 尚未达到，不能用平均帧率宣称已彻底解决。来源文件与对象位置保持不变。

手动验证（尚需在安装版本完成）：打开教程操作.prg，在 15%–40% 左右连续往返缩放，再跨越分组预览阈值。应看到细边框连续保留，缩放明显更顺畅。失败时重点看预览切换是否长时间停顿、边框是否闪烁，以及停止缩放后是否仍持续占用 CPU。跨越阈值仍可能出现短帧尖峰，需要继续测量。
