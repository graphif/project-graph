# 移动时的布局与预览缓存

2026-10-02：更正基准的真实指针后，1029 对象的教程操作项目中，分组同步版本 p95 拖动帧耗时超过 300 ms。定点计时发现 EntityLayerMover 在补偿物理步中反复排序包含树、扫描整个对象集合、重新读取两份全图碰撞边界；布局约束和预览还会处理未变化的关系。隐藏内部连线仍重建曲线。

复用 Godot Dictionary/Array 和几何版本：缓存包含顺序及直接成员映射，归属改变时才重建；物理步只传播位置，派生面板每次渲染前更新一次。TextNode 按成员几何版本缓存边界；GroupOverview 分开比较结构和尺寸，普通平移只更新预览位置。指针拖动让根及后代在同一刚体积分步跟随指针，松手后只给根惯性，后代继续通过包含传播。局部求解排除无可移动权重的碰撞对及其他层的标题；隐藏连线只在物理明确需要或重新显示时刷新。

这属于现有 Godot 节点、物理及缓存协议适配，没有适用的通用第三方库能替代此集成，未增加依赖。所有 Godot 文件通过 MCP 的脚本读取/修改、编辑器脚本执行和原生 PackedScene 导出处理。临时计时和基准入口已清理，保留可重跑的 large_edit_benchmark。

真实发布版基准：Iris Xe、X11 Compatibility、1280×800、119.96 Hz、VSync 开启，每阶段 1.2 秒。

待用户手动验证：重启更新版本，拖动教程操作中的普通节点及“视野操作方法”，再缩小到分组预览快速往返拖动，随后放大。成员应一起运动且连线落在新位置；Shift 多选后拖动多个根，Ctrl 单选后只拖当前根；松手惯性、撤销/重做和保存副本重开应保留包含关系。失败重点检查成员重复位移、隐藏连线恢复后仍在旧位置、跨层放置后缓存未刷新、冷开始明显停顿。更大组、高 DPI、持续 120 Hz 的手感仍待人工验收。
