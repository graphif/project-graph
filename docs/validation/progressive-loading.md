# 渐进加载与首帧分组预览

日期：2026-10-02。打开文件时，后台读取和准备数据与界面绘制并行；主线程按时间预算批量创建原生场景节点。相机中心附近的节点先出现，多个分支按统一时间轴同时展开。分组在加载成员之前取得完整边界和嵌套关系，符合缩放条件的摘要直接参与展开，内部普通节点从首次绘制起隐藏。

## 实际实现与复用选择

- 复用 Godot WorkerThreadPool、ZIPReader、JSON、既有 master MessagePack 适配、FontFile、Dictionary/Array、PackedScene 和 Tween，无新增外部依赖。场景树与渲染对象在主线程创建，后台只准备文档、关系、排序及字体度量。没有把多个线程同时操作 SceneTree 当成并行绘制。
- 分组先创建，外部节点和跨组连线优先，隐藏细节随后补齐。每帧创建预算 12 ms、上限 96 个对象，历史基线分批捕获，避免再次整图编码。临时 ShaderMaterial 只控制现有 Line2D 的展开，结束后恢复原材质；动画不修改保存位置或缩放。
- 可见对象共享约 2.4 秒的目标展开时间，不逐个等待前一分支完成。实际文件解析或对象创建超出预算时仍以真实完成状态为准，不提前宣称已经可编辑。这个时间目标不能保证任意大小、任意硬件下都成立。
- 原生视口 oversampling 的共享位图字体替代冷启动时大量中文 96 px MSDF 生成。屏幕摘要与状态文字单独设置字体采样倍率，避免在很小的舞台倍率下变成模糊低分辨率字形。文本右键菜单延迟到第一次使用创建。
- 评估过多任务同时预热中文字形：同一 TextServer 字体缓存发生锁竞争，实测更慢，未采用。Godot 已提供任务、插值和节点渲染能力，通用异步库不能替代其场景线程约束，因此不引入另一套调度或绘制库。
- 载入中禁止保存部分图、修改和历史操作，允许关闭标签、新建或打开其他文件；根节点持有任务并通过弱引用检测标签关闭。取消一份文件后批量打开继续下一份。读取失败保留原舞台并恢复编辑状态。撤销/重做复用原子恢复，不重播加载动画。

Godot 文件使用 `mcp__godot_mcp__read_script`、`modify_script`、`create_script` 及 `execute_editor_script`；Shader/PackedScene 使用原生 ResourceSaver。没有读取或编辑场景文本，第三方插件未修改。导出时临时移除 MCP 自动加载与编辑器插件，随后按原字节恢复项目配置。

## 实测与验证

发布版，Godot 4.8.dev6、Linux X11、Compatibility、Intel Iris Xe，1280×800 窗口。从调用载入开始计时，包含后台读取/准备、对象恢复、动画及历史基线。测试隔离配置，不修改桌面源文件。

| 文件 | 恢复对象数 | 首批可见 | 完成并可编辑 | p95 帧时 |
| --- | ---: | ---: | ---: | ---: |
| 教程操作.prg | 1029 | 251 ms | 2535 ms | 20.55 ms |
| 教程节点.prg | 180 | 84 ms | 2563 ms | 9.09 ms |
| tutorial-shortcut-keys-3.1.prg | 625 | 160 ms | 2209 ms | 17.93 ms |

另一轮 1029 对象测试同时截取 2.4 秒及完成后的画面：258 ms 首批可见、2533 ms 完成；已查看两张图，分组摘要在 2.4 秒画面中已显示，完成后未再切换整套预览。计时测试中的 `scheduled_view_complete_ms` 是调度目标，不是单独测量的截图完成时间。测试前为校验数量读取一次源文档，磁盘缓存因此可能已热；这些数字不代表操作系统冷盘首次启动的上限。之前调试阶段有 6～7 秒结果，后台负载和调试环境会影响耗时。

同一发布代码载入完成后，1029 对象局部浏览、119.96 Hz 显示器、开启垂直同步：静止 119.56 FPS，平移 119.25 FPS，连续缩放 117.13 FPS；三阶段 p95 约 8.65 ms，布局版本不变。加载期间仍有创建慢帧，不能称为全程锁定 120 FPS。

已通过 progressive_loading、group_overview、native_dirty、text_edit_geometry、navigation_cache、pingfang_font、theme_canvas_sync、connection_continuity、edge_caption、startup_lazy_windows 测试。渐进测试覆盖中心优先、部分帧、完整对象/引用、原位置、干净基线、撤销、解析期和创建期关闭标签、阻止部分保存、取消后继续批量打开、读取失败，以及加载过程即有嵌套摘要、普通细节隐藏、多行标题边界变化小于一个屏幕像素。

三个真实 master 项目各自通过载入、编辑/撤销/重做、另存/重载、附件纹理和原始归档条目逐字节保存、源文件哈希检查。Linux 发布导出与 Godot 编译、Git 空白检查通过。正式主场景通过文件参数连续打开三个教程，载入链约 7.33 秒，未出现脚本错误。环境无 gdformat/gdlint，未执行独立格式化器。startup_lazy_windows 与正式主场景测试自动退出仍有 6 个 ObjectDB 泄漏警告；辅助窗口及正常关闭路径的清理需后续排查。已有 canvas_text_focus 和 edge_caption_magnet 的失败记录见 `large-document-navigation.md`，本次未将其记为通过。

## 用户手动验证（待执行）

1. 运行 `dist/project-graph-local-render.x86_64`，从文件菜单打开 `/home/waya/Desktop/project` 中三个教程。应很快出现中心附近内容，多个分支一起展开，约 2～3 秒完成这三个文件。重点检查长时间空白、只有一条分支慢慢画、状态已完成却漏节点。
2. 加载期间观察分组：应直接显示当前倍率的摘要，内部普通节点不先铺满再被盖住；完成后摘要保持原位置和层级。放大应恢复细节，缩小应保留嵌套摘要。重点检查预览最后突然出现、边界跳动、多行标题截断、覆盖内层后预览消失。
3. 在展开过程中关闭标签，再同时打开多份文件。关闭应响应，下一份继续载入；另存入口不能写出半张图。完成后编辑节点、撤销，另存为测试副本并重开，应保持节点、引用、附件和未保存标记正确。
