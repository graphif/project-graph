# 大图松手时的历史比较

复现：1029 对象的教程拖动已局部化，但松手提交仍约 63～65 ms。`tests/large_edit_benchmark.gd` 设置 `PG_EDIT_PROFILE_HISTORY=1` 对两份真实文档快照做相等比较，原实现先序列化两份 JSON，比较约 44.41 ms，超过 20 ms 测试预算。

采用 Godot 标准 Variant/Dictionary/Array 深比较（`a == b`），不引入依赖或自建哈希。历史捕获、稳定等待、事务边界、撤销/重做和保存编码不变；比较不再为判断是否变化构造两份归档大小的 JSON 字符串。原生字典按键值比较，无关的键插入顺序不再影响是否生成历史。

修改后同一快照比较约 2.22 ms、松手提交约 24.44 ms。真实大图拖动约 195 FPS、p95 6.80 ms；这不是保证每帧都锁定 120 FPS，捕获完整历史快照仍有约 20 ms 开销。

通过大图性能预算、局部拖动的一次撤销/重做、native_dirty、linked_attraction、progressive_loading，以及三个 master 教程的编辑/撤销/重做、另存/重载、原归档和源文件哈希检查。桌面前两个教程已被用户另存为原生格式，旧测试直接对它们执行时只有“master 格式检测”断言失败；随后从其保留的原始 legacy 条目在临时目录重建 master 测试副本，三份完整兼容回归通过，未修改桌面文档。使用 Godot MCP 的脚本修改、原生执行与编译检查；Git 空白检查通过，未安装独立格式化器。

人工验证待执行：打开大图，拖动后松手，停顿应缩短；撤销/重做应各恢复完整手势与邻居让位。对未改变内容的点击/取消编辑应不产生额外历史。重点检查空撤销步骤、只恢复部分对象、保存后未保存标记异常。其他硬件和更大文件尚未实测。
