# 分组缩放概览

日期：2026-09-29。Godot 版已实现覆盖式分组概览，专项图形回归通过；真实鼠标/触控板与输入法体验待用户验收。

## 行为与 master 对齐范围

- 复用 master `SectionMethods.isSectionBigTitleActive` 的两个条件：界面缩放不大于 45%，并且分组在视口中的最长边小于视口最长边的 15%。Godot 的 100% 对应 Camera2D.zoom = 2，因此先按相机基准换算缩放百分比。
- 达到条件后，在原分组边界内显示适配尺寸的居中大标题，隐藏内部节点、嵌套分组和共同属于该概览分组的内部连线/标签。跨分组及连接外部节点的连线继续显示，伸入概览色块的线段由色块遮挡。
- 继续缩小时，较大的外层分组接替内部标题；放大后恢复原内容、编辑控件及命中行为。相机最低缩放从 25% 扩展到 1%，使较大图也能进入概览。
- 概览状态下点击、右键连线起点、Alt 层级放置、框选、全选及切割按可见分组处理，不穿透选中隐藏内容。双击分组大标题复用原生文本编辑器；程序触发内部节点/关系名称编辑时，先恢复相关祖先的详情。
- 仅改变 CanvasItem 的渲染层和 GUI/鼠标命中设置，保留刚体可见性、碰撞形状、坐标、引用及导出属性。缩放不提交历史，也不改变磁性斥力的参与对象。删除、快照恢复、撤销会清理并重建临时概览节点。
- 本次实现用户要求的“大标题覆盖并隐藏详情”，默认生效；未移植 master 的顶部标题模式、关闭模式及设置界面。当前 Godot 没有 master 的虚线/无边框 Section 类型开关。小于 20 视口像素时省略标题绘制，保留框及命中。

## 复用与实现

评估后采用 Godot 内置 Panel、Label、Font 文本度量、CanvasItem.visibility_layer、Dictionary、PackedScene，以及现有 TextNode、容器关系和 ContinuousCorners 样式。master 的 TypeScript/Canvas 渲染器不能直接运行在 Godot；移植其判定与层级语义即可。通用图布局库不适合这个纯视图问题，无需新依赖，也不另写绘制或文本选择引擎。

新增 `src/group_overview.gd` 及其场景，作为 Stage 的工具节点；场景声明 Panel/Label 模板，脚本管理临时实例。Stage、LineEdgeCreator、EntityLayerMover、StageObjectSlicer 的命中与选择调用统一隐藏查询；相机补齐已有代码引用的基准缩放常量并降低最小缩放。

Godot 文件使用 `mcp__godot_mcp__` 的脚本读取、创建、修改、编辑器脚本执行类别处理。场景通过 PackedScene/ResourceSaver 操作，不读取或修改场景文本。现有工作区的其他修改不包含在本功能提交中。

## 用户手动验证

1. 保存当前文档并重新运行项目，准备两个含子节点、内部连线、跨组连线的分组。在 Linux 使用 Ctrl+滚轮或触控板捏合持续缩小：低于 45% 且分组足够小时，应只显示分组大标题和跨组关系。大分组需要继续缩小，最低可到 1%。重点检查内部文字/连线是否残留、跨组线是否消失。
2. 点击、右键、拖动概览分组，再放大：应操作整个分组，恢复后相对布局不变。重点检查是否误选、误连或误切隐藏节点。
3. 双击大标题，全选、插入文字、定位首尾并提交或 Esc 取消；放大后编辑普通节点和关系名称。应沿用原文本编辑体验，检查裁字、光标、选区或焦点异常。
4. 缩小嵌套分组，观察外层标题接替内层；再保存重开、删除分组并撤销。应完整恢复成员和关系，不遗留大标题、空框或失效对象。
