# 首版设计决定

状态：面向首版的设计约束；不是已经落地的类结构。

## D1：渐进分离内容和呈现

沿用现有稳定 ID 与舞台对象，首版允许一对象一呈现。在内容访问接口上区分正文、详情、证据与位置、尺寸、外观，避免新增两份可独立写入的正文。未来 Item/Occurrence 分离需要专门迁移，当前不为每个舞台对象强造第二套 ID。

## D2：三类结构独立

空间包含、主题层级、语义关系各有含义。首版不重写旧主题推导，也不把自由边文字升级为强类型事实。未来迁移需要显式边类别和旧文件解释规则；隐藏箭头只改外观。

## D3：节点表达界面，事务承载修改

预览、连线标签和反馈使用 Godot 节点。交互工具与持久对象分离；场景结构通过 Godot MCP 操作，禁止文本读取或编辑场景文件。详情编辑、来源修改、关系文字修改分别以完整用户操作提交。取消恢复原值，后台任务不直接改活动场景树。

## D4：文件可靠优先

加载先在临时数据中检查完整性，再替换活动文档。未知类型/字段及无效引用无法无损保留时拒绝有损打开，明确原因。保存采用临时写入、完成检查、可恢复替换；具体刷新、替换和失败恢复行为须按目标平台验证，不能声称重命名天然保证掉电安全。

首版继续评估现有 ZIP/JSON，不同时引入另一个权威数据库。所有新增字段进入保存、复制和历史同一条数据通路。

## D5：来源的最小结构

来源信息包含标题、地址、定位说明和摘录；可以附在节点或关系上。缺少地址不阻止记录摘录。首版可将证据记录作为所属对象的结构化数据，复制时独立复制，不要求全局来源库。正文编辑不修改摘录；首版不提供来源自动更新与修订追踪保证。

## D6：先复用，再引入依赖

本次只有文档整理，未引入依赖。实施时优先评估已有注册表、历史、输入控件及 Godot 的 JSON、ZIP、文件接口、字符串匹配与容器。它们是复用候选，不代表未验证 API 已兼容。

| 候选 | 首版处理及理由 |
| --- | --- |
| Godot 原生能力与现有项目服务 | 优先复用；只补字段、校验、事务和界面适配 |
| SQLite/FTS5 与 godot-sqlite | 暂缓；当前切片先扩展已有搜索，未证明需要新权威存储；中文与平台构建仍待评估 |
| ELK/elkjs、Graphviz | 暂缓；自动布局不在首版，额外运行时与分发成本尚无必要 |
| Automerge、Yjs | 暂缓；协作不在首版，先稳定单用户语义 |

候选证据与原始链接见 [调研第 11.4–11.5 节](../research/software-design.md)。正式引入时重新核实精确版本、SHA-256、许可证及传递依赖、Godot/ABI、编译器、OS/CPU、运行时与 I/O 模型；不得把本表视为兼容性验证结果。
