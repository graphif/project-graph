# 画布规模压力测试（2026-09-29）

## 结论

当前版本在几十个节点时开始掉帧，几百个节点时已明显迟滞。1000 个节点加 999 条连线仍能加载，但平移缩放仅约 1.6 FPS，单帧最长约 831 ms。没有观察到崩溃或永久无响应，1000 不是已证明的容量硬上限。

文件体积不能代表可编辑性：1000 个节点加连线的压缩 `.prg` 仅约 69 KiB。重复短文本压缩率高，真实长文本、图片或复杂分组会产生不同结果。

## 环境与方法

- Intel Core i9-13900H，14 核 / 20 线程，约 30 GiB 内存；Intel Iris Xe / Mesa。
- Godot 4.8-dev6 official，Compatibility 渲染器，原生 Wayland，1280 × 800 图形窗口。
- 使用当前工作区和编辑器可执行文件启动独立游戏进程；不是 headless 测试，也不是已安装 release 二进制的专项性能认证。
- 保留用户现有桌面应用与 Godot 编辑器，没有强制关闭进程；同一时间仅运行一个压测实例，RPM 压缩和安装不与采样并行。
- 每个节点包含短中英文文本，采用默认物理和主题设置。节点按 400 × 120 世界单位排布，实测最大宽度 278–293，小于间距，避免初始横向重叠。
- 纯节点与链式连接分别测试；带连线场景有 N−1 条连线。没有图片、分组嵌套、长正文或连线文字。
- 先真实保存，再通过文档加载接口重新加载；随后在全图概览下分别采样静止与平移/缩放各 3 秒。
- FPS 来自实际 process_frame 墙钟间隔，P95 是 95% 帧耗时不超过的值。低 FPS 档样本数较少，只能作为当前环境下的近似值。
- 先用 260 间距初测，再以 400 间距复测；表格使用后者。空画布基线沿用初测。结果不是多轮平均或跨设备保证。

## 代码检查与后续定位

本次只添加压测脚本和结果文档，没有修改性能实现。复用 Godot 的节点注册表、文档保存/加载、Time、FileAccess 和 Performance API，没有新增依赖。

静态检查发现以下可疑开销，尚未进行 profiler 占比确认，不能直接当作已证明的根因：

1. `src/entity_layer_mover.gd` 的 `_process` 和 `_physics_process` 均调用 `refresh_layout`，遍历并排序实体。
2. `src/stage_object/entity/text_node/text_node.gd` 的 `update_container_layout` 对普通节点调用 `_update_collision_shape`；后者重新建立 RectangleShape2D。即使无编辑操作，布局遍历仍会走到这里。
3. 连线额外增加几何、样式及节点处理；同规模下加连线后的明显掉帧值得单独剖析。

下一步应通过 profiler 区分脚本、物理与渲染开销，再评估按变化更新布局/碰撞形状、缓存静态几何和可见范围处理；不要仅靠降低抗锯齿画质掩盖问题。

## 复测与手动验证

测试入口：[performance_stress.gd](../../tests/performance_stress.gd)。所有 Godot 文件修改与测试启动均通过 Godot MCP 的脚本读写及编辑器脚本执行类别完成。

通过 `mcp__godot_mcp__execute_editor_script` 调用 `OS.execute`，运行同版本 Godot，传入项目路径、`--script res://tests/performance_stress.gd -- 100 linked`；用 `/usr/bin/env XDG_DATA_HOME=/tmp/pg-stress-data` 隔离用户数据，并用外部 timeout 限制每档最多 90 秒。`plain` 测纯节点，`linked` 测链式连线。测试会自动退出，JSON 的 phase 应为 complete，loaded 应为 true；日志应包含 STRESS_RESULT，不能出现脚本错误。

运行产物位于 `/tmp/pg-stress-<数量>-<plain或linked>.prg` 和同名 `.json`。这些是可清理的临时测试文件，不是用户文档。

用户可从“文件 → 打开”依次打开 `/tmp/pg-stress-50-linked.prg`、`/tmp/pg-stress-100-linked.prg` 和 `/tmp/pg-stress-300-linked.prg`，缩放至全图并平移，比较跟手程度；还可尝试拖动节点和编辑文字。预期节点数增加时延迟明显增加。若小规模也异常卡顿，重点记录缩放比例、连线数、分组嵌套、后台负载及窗口分辨率。

尚未执行：用户手工输入与拖动的延迟测试、深层分组、图片/长文本/高密度连线、长时间运行，以及已安装 release 包在其他设备上的复测。
