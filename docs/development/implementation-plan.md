## 开工与提交纪律

每项开始前检查相关工作区变化，避免把已有未提交功能混入提交。先选定复用能力，补齐字段模式与失败行为，再改代码。若工作项出现可独立回滚的多个问题，拆成多个原子提交。

获得相应授权后执行与改动相关的测试、构建及格式检查；当前授权只覆盖文档检查和本次文档提交。不得把该授权扩展到 Godot 运行。自动测试优先通过用户命令/存储边界验证外部行为，具体复用哪个既有测试入口在 P0 中确认，不凭空指定已存在的测试能力。

每次交付更新源码证据、实际检查结果、未执行事项和手动步骤。存在数据丢失或撤销不一致时不继续堆叠新能力。

## 首版之后

按调研顺序评估稳定阅读、知识复用，再考虑 AI/协作。折叠、锁定、多视图与自动布局分别需要新规格；历史清单中的其他能力不是自动承诺。

**下一项：P0 补齐基线，随后从 P1 加载前完整性保护开始代码开发。**

UI0/UI1 的规范与验收编号见 [UI 风格与一致性](../design/ui-style.md)。保存保护仍优先；UI 整改按明确缺口推进，不借机重做整套视觉。
